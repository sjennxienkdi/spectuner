# benchmarks/w2 — 真实内容负载复核（含一次负载口径事故的披露）

## 目录内容的更正说明（重要）

本目录的 `w3_A0 / w3_mtp3 / w3_A4 / w3_A6p` 四个子目录是 **W2 窗口首轮**跑出的
锚点臂——事后核对 manifest 发现其负载配置沿用了 random（2K/256），**并非真实
内容负载**。它们保留在此作为 random 负载的补充锚点，**不得当作 W2 真实负载结果
引用**（manifest.json 内的 `workload.dataset: random` 可自行验证）。

## 真实的 W2 复核（更正版，n=3）

见 `w2c_agg.md` / `w2c_agg.csv`（90 条 sharegpt 来源固定 prompt，三类内容各 30 条，
输入 16~119 token，输出上限 256）。关键结果：

| c64 配置 | out tok/s | vs A0 | TTFT med/P99 (ms) |
|---|---:|---:|---:|
| A0 none | 1250.7 | 1.000 | 285 / 354 |
| MTP3 | 2108.1 | **1.686** | 347 / 356 |
| A4 adaptive | 1390.8 | 1.112 | 3935 / 5979 |

**负载分层结论**：random 2K/256 下高并发投机臂吞吐与 TTFT 双输（见
`../confirm/`）；真实内容短输入负载下 MTP3 c64 吞吐 1.686×、TPOT 21.9ms
（A0 为 36.5ms），仅 TTFT 中位 +62ms。**投机收益高度依赖负载构成，
任何"高并发开/关投机"的结论都必须注明负载类型。**

W2 与 random 矩阵同时改变了内容与长度分布，是负载敏感性证据而非单变量因果。
